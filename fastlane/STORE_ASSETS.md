# Store assets & fastlane

This directory publishes Healthy's **store listing** — metadata, screenshots,
icons and the Play feature graphic — to **App Store Connect** and **Google
Play** via [fastlane](https://fastlane.tools).

App **binaries** are built and submitted by EAS (`pnpm build-ios` / `submit-ios`,
`pnpm build-android` / `submit-android`). fastlane only pushes the listing.

> `README.md` in this folder is auto-generated by fastlane; keep real docs here.

## Why fastlane lives at the repo root

Expo Continuous Native Generation regenerates and `.gitignore`s `ios/` and
`android/`, so nothing durable can live inside them. All fastlane config, copy
and images live here under version control, with paths pinned in `Deliverfile`
and `Fastfile`. Unlike fastlane's default, we **do** commit screenshots — they
are curated marketing assets, not app-captured throwaways.

## Where assets come from

Screenshots, icons, the feature graphic and all copy are produced by the Claude
Design project **"Store Assets.dc.html"**
(`https://claude.ai/design/p/2653c7eb-034f-49b5-aa45-d6f7bb0962bc`), which
renders every frame at the exact size each store requires. To refresh, edit the
design doc, re-export, and drop the PNGs into the layout below.

## Layout

```
fastlane/
  Appfile Deliverfile Fastfile   # config
  metadata/
    listing-copy.md              # canonical copy; .txt files derive from it
    ios/en-US/                   # deliver metadata (name, subtitle, …)
    android/en-US/               # supply metadata (title, descriptions, changelogs)
      images/                    # supply icon + featureGraphic + screenshots
  screenshots/
    ios/en-US/                   # iPhone 6.9" x6 + iPad 13" x3 (device auto-detected)
    _alternates/{6.7,6.5}        # kept for when Connect asks for those sizes
  store-icons/                   # 1024/512 segmented-heart icon (reference)
```

### iOS screenshots (App Store Connect)

deliver detects the device family from each image's resolution. Upload **one**
iPhone set.

| Location | Size | Family | Count |
| --- | --- | --- | --- |
| `screenshots/ios/en-US/` (iPhone) | 1320 × 2868 | iPhone 6.9" | 6 |
| `screenshots/ios/en-US/` (iPad)   | 2064 × 2752 | iPad Pro 13" | 3 |
| `screenshots/_alternates/appstore-6.7/` | 1284 × 2778 | iPhone 6.7" | 6 |
| `screenshots/_alternates/appstore-6.5/` | 1242 × 2688 | iPhone 6.5" | 6 |

If Connect rejects 6.9", move a `_alternates/` set into `screenshots/ios/en-US/`
(replacing the iPhone shots, keep the iPad ones) and re-run.

The iOS **app icon** comes from the binary, so deliver does not upload it;
`store-icons/icon-1024.png` is a design proposal kept for reference.

### Android assets (Google Play)

supply reads from `metadata/android/en-US/images/`:

| Path | Size | Count |
| --- | --- | --- |
| `images/icon.png` | 512 × 512 | 1 |
| `images/featureGraphic.png` | 1024 × 500 | 1 |
| `images/phoneScreenshots/` | 1080 × 1920 | 6 |
| `images/sevenInchScreenshots/` | 1200 × 1920 | 3 |
| `images/tenInchScreenshots/` | 1600 × 2560 | 3 |

## Names

- **iOS App Store name:** `Healthy: Local Health Coach` — App Store names must be
  globally unique, and plain "Healthy" is taken by another account. The
  home-screen icon name stays "Healthy" (that comes from the app binary).
- **Google Play title:** `Healthy` — Play allows duplicate titles.

## Prerequisites

```bash
gem install bundler
bundle config set --local path 'vendor/bundle'   # avoids writing to system gem dir
bundle install
```

### App Store Connect auth (recommended: API key)

App Store Connect → Users and Access → Integrations → App Store Connect API:

```bash
export ASC_KEY_ID=XXXXXXXXXX
export ASC_ISSUER_ID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
export ASC_KEY_PATH=./fastlane/AuthKey_XXXXXXXXXX.p8   # git-ignored
```

Without these, deliver falls back to interactive Apple-ID login (Appfile
`apple_id`).

### Google Play auth (service account)

```bash
export SUPPLY_JSON_KEY=./service-account-key.json      # git-ignored
```

## Uploading

```bash
bundle exec fastlane ios store_assets       # App Store Connect (no binary)
bundle exec fastlane android store_assets   # Google Play (no binary)

# dry-run Google Play without committing changes:
SUPPLY_VALIDATE_ONLY=true bundle exec fastlane android store_assets
```

Both lanes skip binary upload and never submit for review — a human does the
final "Submit for review" in each console.

## Refreshing assets

1. Edit **Store Assets.dc.html** in Claude Design and re-export `store-assets/`.
2. Copy the PNGs into the layout above (same filenames, same folders).
3. Update `metadata/listing-copy.md` and the derived `.txt` files if copy changed.
4. Commit, then run the upload lanes.
