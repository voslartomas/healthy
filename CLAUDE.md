# CLAUDE.md

Guidance for AI assistants working in this repository. Read this before making
changes; it captures the structure, workflows and conventions that are not
obvious from any single file.

## What this is

**Healthy** (`healthapp`) is a privacy-first health companion for iOS + Android,
built with **React Native 0.86 + Expo SDK 57** and TypeScript in **strict** mode.
Everything runs on the device: health data is read from the OS store, the app
database is local SQLite, and the AI coach runs a downloaded Gemma model through
`llama.rn`. There is **no backend of our own** — see the privacy invariants below.

Screens: Today (daily brief), Nutrition, Strength (lift), Trends, Settings, plus
detail screens (Recovery, Cardio, Sleep) and a global Coach FAB/modal.

## Commands

```sh
pnpm install --frozen-lockfile
pnpm start          # Expo dev server
pnpm dev            # dev-client
pnpm android        # APP_VARIANT=dev expo run:android → installs as cz.dev.healthy
pnpm ios            # expo run:ios (macOS only) → cz.healthy
pnpm test           # jest (jest-expo preset)
pnpm lint           # eslint (flat config, eslint-config-expo)
pnpm typecheck      # tsc --noEmit, strict
pnpm format:check   # prettier --check .
```

**Before finishing any change, run `pnpm typecheck`, `pnpm lint` and `pnpm test`.**
There is no CI in this repo (`.github/` does not exist), so these local checks are
the only gate. `pnpm format` (Prettier) fixes formatting.

`pnpm android` sets `APP_VARIANT=dev`, which `app.config.ts` uses to rename the
Android package to `cz.dev.healthy` so the dev build installs *alongside* the
production app the owner uses daily. Every other entry point leaves it unset.

## Continuous Native Generation — never edit `android/` or `ios/`

This is a **CNG** project. `android/` and `ios/` are gitignored build artifacts
regenerated by `pnpm expo prebuild` from `app.json` + the config plugins in
`plugins/`. Any native change must be expressed as:

- an entry in `app.json` (`plugins`, `permissions`, `infoPlist`, `entitlements`), or
- a config plugin in `plugins/`.

The three local plugins encode hard-won native fixes — read their header comments
before touching them:

- `plugins/withHealthConnect.js` — Android Health Connect read/write permissions,
  the `<queries>` entry, the permission-rationale intent-filter + Android 14
  `VIEW_PERMISSION_USAGE` alias, and `minSdkVersion 26`.
- `plugins/withRnllamaGradleProps.js` — `rnllamaBuildFromSource=true` (required,
  or the coach dies with "JSI bindings not installed"), ABI narrowing to
  `arm64-v8a` (`RNLLAMA_EMULATOR=1` / `RNLLAMA_ABIS` to widen), opt-in ccache via
  `RNLLAMA_CCACHE=1`, Gradle daemon tuning.
- `plugins/withNotifeeRepo.js` — points Gradle at Notifee's bundled local `.aar`
  repo, without which the Android build cannot resolve `app.notifee:core`.

## The three architectural layers you must respect

### 1. Health data: adapter → derivation → store

```
HealthConnectSource / HealthKitSource  (platform adapters, implement HealthSource)
        ↓ normalized RawHealthData (multi-source, NOT deduped)
src/health/derive.ts                   (dedup, baselines, readiness, cardio, trends)
        ↓ HealthSnapshot (deduped, aggregated)
src/state/useHealthStore.ts            (the only thing the UI sees)
```

- `src/health/HealthSource.ts` is the contract; `deviceHealth.ts` picks the
  adapter by platform (`Platform.OS === 'ios' ? HealthKit : HealthConnect`) and
  memoizes it. **Never branch on platform above this layer.**
- Adapters return `null` on unavailable/unauthorized — never a throw, never
  fabricated data. `src/health/index.ts` turns that into `EMPTY_SNAPSHOT`, and the
  UI renders `-` for missing metrics. **Do not invent placeholder health values.**
- All correctness-critical logic lives in `derive.ts` and is pure + unit-tested
  (`__tests__/health-derive.test.ts` uses a fixed `NOW` epoch for determinism).
  Add logic there, not in adapters or components.
- Samples carry a `source` (writing app package) so `dedupeIntervals`/`sourceRank`
  can de-duplicate Fitbit + Withings + Google Fit writing the same metric.
- **HRV is not comparable across platforms**: Health Connect reports RMSSD,
  HealthKit reports SDNN. Every value is tagged with `hrvAlgorithm`; never mix them.
- Load strategy: one deep 12-week read is cached (memory + SQLite `health_cache`);
  routine/foreground refreshes fetch only the recent slice and splice it on via
  `mergeRaw`. `RECENT_SPLICE_DAYS` must stay consistent with `LIGHT_WINDOWS`.
- **The only write** the app performs is user-authored nutrition
  (`createFoodEntry`/`deleteFoodEntry`). Everything else is read-only.

### 2. Persistence: repository → service → store

Each SQLite table gets exactly one repository in `src/db/`; repositories are the
**only** modules that contain SQL. Services in `src/state/*Service.ts` orchestrate
"write-through to SQLite, then update the store". UI code calls services, never
repositories or `getDb()` directly.

```
src/db/goalsRepository.ts   ← the only place that knows the goals SQL
src/state/goalsService.ts   ← createGoal/removeGoal/initGoals (write-through thunks)
src/state/useGoalsStore.ts  ← pure, synchronous zustand reducers + pure selectors
```

Every `init*()` service function is called once from `App.tsx` on startup; add
yours there if you introduce a new persisted domain.

**Schema changes** go in `src/db/database.ts`:

- Tables use `CREATE TABLE IF NOT EXISTS` — edit the DDL in place. Because that
  never alters an existing table, columns added later also need a guarded
  `ALTER TABLE` in an `ensure*Columns` helper (SQLite has no
  `ADD COLUMN IF NOT EXISTS`).
- One-time *data* migrations go in `runMigrations()`, keyed on
  `PRAGMA user_version` (currently at 3). Add a new `if (version < N)` block and
  bump the pragma.
- Rows carry `created_at`/`updated_at` (and `remote_id` where relevant) so a
  future cloud sync is not a destructive change (ADR-002).

### 3. State: zustand stores + pure selectors

- Stores hold state and **pure, synchronous reducers only** — that is what makes
  them testable without a native database.
- Derived values are **exported pure functions**, not store methods:
  `goalCurrent`, `goalProgress`, `goalWeekly`, `countMatchingSessions`,
  `weeklyDeficitAvg`. Components pass their reactively-subscribed values in so the
  live tile and the history grid can never disagree. Reuse these rather than
  recomputing.
- `useAppStore` persists through **SecureStore** (`zustand/middleware` `persist` +
  `createJSONStorage`) because it can hold an API key; `partialize` deliberately
  excludes health-connection state, which is re-derived on launch.
- Async side effects live in services/thunks, and are fired with
  `void x().catch(err => console.warn(...))` — never left unhandled.
- Module cycles are real here: `useHealthStore` imports `goalHistoryService`
  lazily via `await import()` to break one. Prefer restructuring, but follow the
  existing pattern if you hit the same cycle.

## AI coach

- `src/features/coach/aiClient.ts` — provider-agnostic `runCoach()` with a
  bounded tool-calling loop (`MAX_TOOL_ROUNDS`, `MAX_TOKENS`) and one wire-format
  loop per provider. Cloud providers still exist in `PROVIDERS`, but the shipping
  default is `ondevice` and Settings no longer offers the cloud ones.
- `src/features/coach/ondevice/` — the on-device path:
  - `models.ts` is deliberately **pure** (no `llama.rn`, no `expo-file-system`) so
    it can be imported by `useAppStore` and unit-tested. It owns the Gemma model
    registry, the chat-template renderer (Gemma has no system role and requires
    strictly alternating turns), the GBNF `ACTION_GRAMMAR`, and `parseAction`.
  - Small Gemma models are unreliable at native tool tokens, so output is
    grammar-constrained to a single JSON action object (`{"tool":…}` or
    `{"reply":…}`) which the runner parses. Prompt/protocol changes belong in
    `buildSystemPreamble`.
  - `runner.ts` takes an **injectable engine** so tests script a fake instead of
    loading `llama.rn`. `llamaEngine.ts` `require`s the native module lazily.
  - `useModelStore` / `useWhisperStore` own download, pause/resume (with a
    `.part.json` resume sidecar) and on-disk status. `App.tsx` pauses in-flight
    downloads on `background` (never `inactive`) and resumes on `active`.
- Tools: `foodTool.ts` (log/list/update/delete food, bridged to the health store)
  and `workoutTool.ts`. `dataContext.ts` builds the null-safe text summary of the
  user's real numbers that grounds both the chat coach and the daily brief.
- Voice input (`useVoiceInput.ts`) is platform-split: iOS uses expo-audio's
  LINEARPCM recorder; Android streams raw PCM (`pcmRecorder.ts`) wrapped as a
  `data:audio/wav;base64,…` URI. Both feed the same on-device Whisper engine.

## UI conventions

- The design source of truth is the v3 "data brief" Open Design prototype (see
  ADR-003). Screens are a flat editorial sheet: numbered sections divided by
  hairlines, mono eyebrow rows, oversized mono hero numbers.
- `src/components/brief.tsx` holds that vocabulary (`txt()` and the section
  primitives). Prefer it for new v3 screens; `Card` and friends are the older
  primitives still used by kept screens.
- **Colors only from `src/theme/colors.ts`.** The palette carries both v3 names
  (`ink`, `mut`, `fnt`, `hair`, `track`, `sand`, `acc`, `grn`, `red`, `inv`,
  `scrim`) and legacy aliases (`bg`, `surface`, `fg`, `accent`…). RN cannot parse
  `oklch()`, so values are converted to sRGB hex. Read them through `useTheme()`,
  which resolves light/dark from `useColorScheme()`.
- **Fonts via `sans(weight)` / `mono(weight)`**, never `fontWeight` with a custom
  face — RN maps each weight to a distinct family name. Radii and spacing come
  from `radii` / `spacing` in `theme.ts`.
- Navigation is **param-less**: screens read stores instead of route params
  (see `RootStackParamList` — every entry is `undefined`). Screens are typed
  against the minimal `AppNav` interface in `src/app/navigation/types.ts` and
  wrapped with `asScreen()` in the navigator, so tests can pass `mockNav()`.
- Give pressables `accessibilityRole` + `accessibilityLabel` — tests query by
  label and text.

## Testing

- `jest-expo` preset; `jest/setup.js` stubs the native modules (safe-area,
  Notifee, splash screen, `llama.rn`, `expo-audio`, `expo-file-system/legacy`),
  and `__mocks__/` provides in-memory `expo-sqlite` / `expo-secure-store`.
- Render screens with `renderWithProviders(...)` from `jest/renderWithProviders`
  (it supplies synchronous safe-area insets — the real provider never measures
  under Jest) and pass `mockNav()` as `navigation`.
- Query by user-visible text / accessibility label, not test IDs.
- Pure logic (derivation, goal math, portions, prompt rendering, parsing) is
  tested directly with fixed timestamps — keep new logic pure so it can be too.
- When you add a native dependency, add its stub to `jest/setup.js` in the same
  change, or the whole suite fails at import time.

## Privacy invariants (non-negotiable)

These are the product's core promise; do not weaken them without an ADR.

1. Health data is read from the OS store on-device. Audio, PCM and health records
   never leave the device. Only model *weights* are downloaded over HTTPS.
2. There is no backend of ours. The cloud coach paths, if used, talk device↔provider
   directly with the user's own key; the key lives in SecureStore, never in plain
   storage or logs.
3. Keep the dependency list small — no analytics, tracking, or health-data
   dependencies without an approved ADR.
4. Never fabricate health numbers. Missing data renders as `-`. Readiness is a
   disclosed, non-clinical heuristic over the user's own 30-day baselines
   (ADR-004); it must not be presented as a medical claim.

## Generated files

`src/data/exerciseCatalog.generated.ts` and
`src/features/strength/components/frames.generated.ts` are auto-generated from the
CC0 free-exercise-db, together with the ~575 images in `assets/exercises/`. Their
headers say "Do not edit by hand" and point at `scripts/gen_catalog.py`, which is
**not committed** — if the catalog needs regenerating, that script must be
recovered or rewritten first. Hand-edit only the non-generated
`src/data/exerciseCatalog.ts` (types, labels, filters, lookup helpers). Exercise
`id`s are persisted by saved workouts and logged sessions, so **never reuse or
renumber them**.

## Code style

- Prettier: single quotes, trailing commas, `arrowParens: 'avoid'`. Run
  `pnpm format` rather than hand-formatting.
- ESLint flat config extending `eslint-config-expo`; `android/`, `ios/`, `.expo/`,
  `dist/` are ignored.
- TypeScript strict, `tsc --noEmit` must stay clean — no new compiler warnings.
- Imports: external packages first, then relative, roughly alphabetical (match the
  surrounding file).
- The codebase is heavily and deliberately commented: module-level JSDoc blocks
  explain *why* a module exists and what invariant it protects, and inline
  comments record the landmine that motivated a line. **Match that density** —
  when you fix a non-obvious bug, leave the reason behind in a comment.
- Native modules that may be absent (health, `llama.rn`, sharing, document picker)
  are `require`d lazily at call time so importing a module never drags a native
  dependency into a test.
